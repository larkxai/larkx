---
title: Troubleshooting
description: Cloud errors stay in the exporter. They do not fail the agent.
---

`runtime.telemetryStatus()` and the value returned by `flushTelemetry()` use `lastError`.

| `lastError`    | What to do                                                                                                                                                                                                                                 |
| -------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `unauthorized` | The key was rejected or does not start with `lkx_ing_`. Fix the key, then call `flushTelemetry()`.                                                                                                                                         |
| `rate_limited` | The organization is over the temporary request or event limit. Wait for the backoff. HTTP 429 is also what Cloud returns today for the permanent per-run event cap, so a 429 is not treated as a dead run.                                 |
| `rejected`     | One run was refused. Other runs can still export. On npm {{sdkVersion}} the destination may hold until a manual flush. On the current default branch, `flushTelemetry()` retries `quota_exceeded` only. A history conflict stays rejected. |
| `offline`      | The batch is still local. Execution is unaffected.                                                                                                                                                                                         |
| `redirected`   | The collector returned a 3xx. The exporter does not follow it.                                                                                                                                                                             |
| `unsupported`  | The response was not one this client will treat as success or as a named run rejection. The batch is not marked delivered.                                                                                                                 |

`rejectedRuns` on the status is the count of runs the exporter is skipping, not a list of Cloud dashboard ids.

## The agent still runs

None of these statuses throw out of a tool or a model call. If a run is `BLOCKED`, that is the local runtime waiting for `reconcile` or for a remote condition. It is not a Cloud error. See [Tool side effects](/concepts/tool-side-effects).

## Production schema

If every batch is rejected with an unrecognized payload and the key is valid, compare the deployed Cloud schema with telemetry version 1. This repository records that production on 20 November 2026 still accepted an older schema. Do not point a production app at a collector you have not tried with the installed SDK.
