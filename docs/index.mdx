## Build durable AI agents on devices.

LarkX is an open-source execution runtime for AI agents that run directly on devices, work offline, recover from interruptions, and collaborate with remote agents.

Running a model locally is getting easier. Keeping a multi-step agent correct after the operating system suspends the app, the network drops, or a tool has already changed local data is the harder problem. LarkX is that execution layer. It does not replace an inference engine or a remote agent framework.

## Start here

<Steps>
  <Step title="Decide if this is the right layer">
    Read [When to use LarkX](/getting-started/when-to-use). A one-shot prompt does not need a
    durable runtime.
  </Step>
  <Step title="Install the SDK">
    Add `@larkxai/react-native` {{ sdkVersion }} and create a development build.
    [Installation](/getting-started/installation) separates Expo, bare React Native, local
    inference, and Cloud.
  </Step>
  <Step title="Run Hello World">
    [Hello World](/getting-started/hello-world) uses a scripted model. It proves the runtime, a
    local tool, and the stored result. It is not inference.
  </Step>
  <Step title="Run an on-device agent">
    [Your first on-device agent](/getting-started/on-device-agent) uses the supported Cactus model
    after a one-time download.
  </Step>
  <Step title="Add a remote agent, then Cloud">
    [Your first hybrid agent](/getting-started/hybrid-agent) delegates to a service you already run.
    [Cloud](/cloud/introduction) is optional and comes after a local run works.
  </Step>
</Steps>

The public package is [`@larkxai/react-native`](https://www.npmjs.com/package/@larkxai/react-native). Swift and Kotlin distributions are not published. Expo Go cannot load the native module.

Committed steps are not run again. An effect that left the process before the commit is not exactly-once. Those guarantees live in [Core Concepts](/concepts/durable-execution).
